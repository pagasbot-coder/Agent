## 1. Зачем это Exolve

Exolve = голос, SMS, Telecom API, 8-800, B2B коммуникации.

Антифрод бьёт по трём слоям:

| Слой | Что значит |
|------|------------|
| Регуляторика | обязанности оператора/провайдера: обмен с ГИС, блокировки, маркировка, ВАТС |
| Продукт | правила в API/кабинете, лимиты, статусы номеров, логирование |
| Бизнес | меньше фрода у клиентов, меньше штрафов/претензий, не сломать легальный трафик |

**Не путать:** СОРМ ≠ антифрод.  
- **СОРМ** — доступ уполномоченных органов (126-ФЗ + 144-ФЗ и подзаконка).  
- **Антифрод** — выявление/блокировка мошеннических коммуникаций и обмен сигналами (ГИС «Антифрод» и смежные нормы).

## 2. Нормативная карта

### База телекома и данных

- **126-ФЗ «О связи»** — рамка оператора и услуг  
- **152-ФЗ «О персональных данных»** — ПДн в логах, номерах, сигналах  
- **149-ФЗ** — информация и IT-системы  
- **38-ФЗ «О рекламе»** — массовые вызовы/SMS без согласия  
- **СОРМ:** 126-ФЗ + **144-ФЗ** + подзаконка (не смешивать с антифродом в одном эпике без RACI)

### Антифрод-контур 2025–2027 (по открытым обзорам)

- **41-ФЗ (01.04.2025)** — создание **ГИС «Антифрод»**  
  - оператор системы: Минцифры  
  - пользователи: госорганы, ЦБ, банки, операторы связи и др.  
- Запуск/функционирование ГИС — ориентир **с 01.03.2026** (поэтапно + подзаконка)  
- **Второй пакет** (в обзорах — **210-ФЗ от 26.06.2026**), усиление обязанностей операторов, в т.ч.:
  - выявлять номера «мошенников» и «жертв» → передача в ГИС  
  - приостанавливать услуги / пропуск трафика по мошенническим номерам  
  - маркировка иностранных вызовов, самозапрет гражданина на иностранные вызовы  
  - ужесточение по **ВАТС** (учёт, ограничения — критично для облачной телефонии)  
  - дальше по горизонту: ответственность/возмещение при бездействии, IMEI-база и др. (сроки поэтапные)

**Kickoff must:** реестр НПА от юриста Exolve с датами вступления именно для их лицензии/роли (оператор / агрегатор / партнёр МТС).

### Источники (не замена юристу)

- Обзоры: Пепеляев Групп «Антифрод 2.0», ConsultantPlus по ГИС «Антифрод», ComNews / Interfax / РИА по обязанностям операторов  
- Внутренний артефакт проекта: всегда свежее юр.заключение Exolve

## 3. Типы фрода в зоне Exolve

1. Подмена номера / серый CLI  
2. Голосовой фрод (автодозвон, toll fraud, wangiri)  
3. SMS-фрод и фишинг-рассылки  
4. Компрометация API-ключей / кабинета B2B  
5. Злоупотребление 8-800 и транзитным трафиком  
6. Ложные срабатывания → блокировка легального клиента (бизнес-риск)

---

## 4. Черновик устава проекта

**Название (рабочее):** Соответствие антифрод-требованиям и интеграция с ГИС «Антифрод» (продукты Exolve)

**Цель:** обеспечить выполнение обязательных требований по противодействию мошенническим вызовам/SMS в продуктах Exolve в срок регулятора, без недопустимого роста ложных блокировок для B2B клиентов.

**Не цель (out of scope v1):** «лучший в мире ML-антифрод с нуля»; замена СОРМ; полный финмониторинг банков.

**Стейкхолдеры:** продукт, разработка, ИБ, юристы, сеть/телефония, поддержка, sales/CS; при необходимости — контур МТС.

**Критерии успеха (черновик KPI):**

- 100% обязательных интеграций/процессов к дате N (из реестра юриста)  
- SLA обмена с ГИС 24/7 (если применимо)  
- доля ложных блокировок ≤ X% (X согласовать с бизнесом)  
- time-to-block / time-to-report по сигналу ≤ Y  
- 0 критичных предписаний по просрочке обязательных мер  
- runbook для поддержки и клиентов готов до go-live

## 5. Workstreams

1. **Legal / Compliance** — реестр требований, даты, must/should, ответственность сторон  
2. **Discovery продуктов** — scope: API, SMS, голос, 8-800, ВАТС, кабинет  
3. **Интеграция ГИС «Антифрод»** — каналы обмена, форматы, узлы верификации, журналы, отказоустойчивость 24/7  
4. **Detection & Policy** — критерии «мошенник/жертва» (когда выйдут), правила блокировок, исключения  
5. **Product / UX B2B** — статусы номера, уведомления, апелляции, лимиты API  
6. **Ops** — дежурства, RCA, эскалации, отчётность  
7. **Comms** — FAQ для клиентов, sales enablement

```text
Юристы: реестр обязательств
  → Gap analysis продуктов
  → Архитектура и интеграции
  → Backlog и релизы
  → Пилот и мониторинг
  → Операционка и SLA
```

## 7. Риски

| Риск | Mitigation |
|------|------------|
| Подзаконка запаздывает | инфраструктура обмена раньше, правила конфигурируемо |
| Ложные блокировки B2B | whitelist / апелляции, метрика false positive |
| Путаница СОРМ vs антифрод | раздельные эпики и владельцы |
| ВАТС / облачная телефония | отдельный legal review + product impact |
| 24/7 недоступность узла обмена | NFR: мониторинг, дублирование, алерт |
| Срыв срока регулятора | буфер, еженедельный статус, ранняя эскалация |

## 8. 90 дней

**Дни 1–30:** реестр обязательств, карта продуктов, gap analysis, RACI, черновик архитектуры обмена с ГИС, список вопросов юристам.

**Дни 31–60:** MVP интеграции / журналирования / полуавтоматических процедур; пилот на 1–2 продуктах; метрики и runbook draft.

**Дни 61–90:** расширение на весь scope, автоматизация правил, клиентские сценарии в кабинете, репетиция аудита/отчётности, план фазы 2.

## 9. Шпаргалка на собес (1 мин)

«Антифрод для Exolve — проект соответствия: ГИС «Антифрод», обязанности по выявлению и передаче сигналов, блокировки, маркировка; отдельно — удар по ВАТС и API-телефонии. СОРМ не смешиваю с антифродом. Подход: реестр НПА → gap по продуктам → план-график под даты регулятора → интеграции и операционка → метрики ложных срабатываний, чтобы не убить легальный B2B трафик.»

### Пробелы кандидата (говорить честно)

- Прямых переговоров с Роскомнадзором по продуктам нет  
- Глубокой архитектуры СОРМ нет  
- Отдельный antifraud engine оператора не строил  
- Близко: Beeline — сроки, риски, интеграции, Problem Management, мониторинг; госконтур — НПА и жёсткие дедлайны
